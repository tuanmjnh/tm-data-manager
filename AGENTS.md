## Nuxt 4 Directory Structure & Path Aliases Standard

According to official Nuxt 4 documentation (https://nuxt.com/docs/4.x/api/nuxt-config), frontend code in Nuxt 4 apps is separated into the `app/` directory (`srcDir`):

| Alias / Prefix | Target in Nuxt 4 | Proper Usage & Scope |
| :--- | :--- | :--- |
| `~/` or `@/` | `<rootDir>/app` (`srcDir`) | Internal frontend application files (components, composables, pages, layouts, assets, app-only utils/types). |
| `~~/` or `@@/` | `<rootDir>` (Root Project) | Files located at project root outside `app/` (e.g. `~~/config/...`, `~~/scripts/...`, `~~/layers/...`). Never use `~~/app/...`. |
| `#shared/` | `<rootDir>/shared` | Code, utilities, constants, and TypeScript types shared across BOTH App (Frontend) and Nitro Server (Backend) (e.g. `#shared/types/...`, `#shared/utils/...`). |
| `#server/` | `<rootDir>/server` | Internal Nitro Server files (services, modules, database, server-only utils/types). For use within `server/`. |
| `#imports`, `#app`, `#build` | `<rootDir>/.nuxt/...` | Virtual modules and system files automatically generated by Nuxt during build. |

### Strict Architectural Boundaries

1. **NEVER use `~/server/...` or `@/server/...`**: Since `~/` points to `<rootDir>/app`, `~/server` will look inside `app/server`, which is incorrect.
2. **Frontend (`app/`) MUST NEVER import from `server/`**: Never use `import ... from '~~/server/...'`, `from '#server/...'`, or relative paths into `server/` from any file inside `app/`. Client code must never bundle or depend on server modules.
3. **Server (`server/`) MUST NEVER import from `app/`**: Never use `import ... from '~~/app/...'` or `from '~/...'` inside `server/`. If code or types are needed by both frontend and backend, extract them to `shared/`.
4. **Shared Code Placement (`#shared/`)**: Any interface, DTO, enum, validator schema, or helper function shared between client and server MUST reside in `<rootDir>/shared/` (e.g., `shared/types/`, `shared/utils/`) and be imported via `#shared/...`. Do NOT use fragile relative traversals like `../../shared` or `~/../shared`.
5. **Server Internal Alias Discipline (`#server/`)**: Within `server/` (including `server/api/`, `server/routes/`, `server/middleware/`, `server/modules/`), ALWAYS use the `#server/` alias (e.g. `#server/modules/...`, `#server/utils/...`, `#server/config`) instead of multi-level relative traversals (`../../../../`).
6. **Type Placement Discipline**:
   - App-only types: `app/types/` (import via `~/types/...` or auto-import).
   - Server-only types: `server/types/` (import via `#server/types/...` or relative within `server/`).
   - Shared types: `shared/types/` (import via `#shared/types/...`).
   - There is NO root-level `types/` folder.
7. **Project Root References (`~~/`)**: Use `~~/` or `@@/` ONLY for files truly at the project root outside `app/` and `server/` (e.g. `~~/scripts/...`). Never use `~~/app/...` (use `~/...` instead).
